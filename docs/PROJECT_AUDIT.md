# FundOS 项目整体审计

审计日期：2026-07-21  
审计范围：产品需求、领域模型、计算逻辑、数据源、工作流、API、界面、运营管道、部署与测试。

## 1. 总体结论

FundOS 已经从概念文档发展为可运行的投资组合运营 MVP，具备完整的模拟闭环、明确的风险否决机制、组合版本管理、业绩计算、研究证据关联、投委会审批、复盘归因、API、产品台和生产运行管道。

当前适合：

- 产品演示；
- 教学和研究；
- 单团队内部模拟盘；
- 继续验证资产配置逻辑和运营流程。

当前不适合：

- 对公众直接提供正式投资建议；
- 自动实盘交易；
- 多租户或多实例生产运行；
- 将 ETF 代理表现宣称为指数基金组合的真实业绩；
- 在无额外验证的情况下证明策略具有稳定投资能力。

成熟度判断：

| 场景 | 估计成熟度 | 判断 |
|---|---:|---|
| 产品演示 | 90% | 已具备完整故事线和界面 |
| 内部模拟盘试运行 | 70% | 数据和流程可运行，需补真实数据验证 |
| 小范围受控试点 | 55% | 需补身份、备份、合规和稳定性 |
| 面向公众正式上线 | 30% | 尚缺数据授权、合规、长期业绩和生产安全 |

## 4. P0：正式试点前必须处理

### 4.1 真实 Agent 尚未接入

当前研究、组合提案和复盘的数据结构已经完成，但没有实际的大模型调用、Prompt 版本、模型输出校验、Token 成本和模型执行日志。现状更准确地说是“支持 Agent 输出的工作流”，还不是自动运行的多 Agent 系统。

验收要求：

- 接入至少一个模型供应商；
- 使用严格结构化输出；
- 保存模型、Prompt 版本、输入摘要、原始输出和人工修改；
- 模型异常不能污染数据库；
- 数值计算继续只由确定性程序完成。

### 4.2 真实投资数据口径不足

当前真实数据使用 ETF 代理，且采用普通收盘价。尚未完整处理：

- 分红和拆分后的复权价格；
- 场外基金净值确认时间；
- 申购赎回费用；
- 不同市场交易日；
- 汇率转换；
- 数据供应商授权与再分发权利。

验收要求：建立正式数据字典，明确每个内部资产、产品标的、基准、币种、时区和复权口径。

### 4.3 回测存在过度简化

当前计算未纳入交易成本、滑点、场外基金确认延迟和现金流。多资产日期对齐使用共同日期交集，可能隐藏某项资产缺失交易日，而不是显式暴露缺口。

验收要求：

- 使用正式交易日历；
- 明确调仓决定、成交和生效时点；
- 纳入费用、滑点和税费；
- 区分缺失、休市和未更新；
- 增加样本外测试及前瞻模拟盘。

### 4.4 身份与权限不足

目前只有一个全局 API Key，不能区分组合经理、风控和投委会成员，也不能证明审批人的真实身份。

验收要求：

- 身份认证；
- 基于角色的权限控制；
- 审批人不可由请求正文任意填写；
- 关键审批增加不可抵赖审计信息；
- API Key 支持轮换和撤销。

### 4.5 数据恢复与生产验证不足

已有容器和备份要求文档，但尚未实际验证 Docker 构建、远程 CI、数据库备份恢复和告警端到端发送。

验收要求：

- GitHub 仓库实际运行 CI；
- 构建并启动生产镜像；
- 完成一次数据库恢复演练；
- 验证 Webhook 接收端；
- 形成恢复时间和数据丢失目标。

### 4.6 合规边界需要正式确认

面向公众展示投资组合、研究意见和历史表现前，需要法律及合规评估。必须清楚区分模拟业绩、代理资产表现和真实可投资产品表现。

验收要求：风险揭示、数据免责声明、模拟业绩标识、利益冲突披露及适用地区规则全部完成审核。

## 7. 技术风险清单

| 风险 | 严重度 | 当前缓解 |
|---|---|---|
| 日期交集掩盖缺失行情 | 高 | 数据新鲜度检查，但未覆盖逐日缺口 |
| 普通收盘价导致收益偏差 | 高 | 文档标记为 ETF 代理 |
| 单一 API Key 无法证明审批身份 | 高 | 写接口受保护，但无角色身份 |
| SQLite 多写入并发 | 高 | 文档限定单实例 |
| 短样本年化指标失真 | 中 | 指标可复算，但界面未提示样本长度 |
| SQLite 单写者限制横向扩展 | 中 | 原子幂等已完成；多实例前迁移 PostgreSQL |
| Webhook 地址配置错误或不可达 | 中 | 告警落库并支持重试 |
| 供应商限流或数据变更 | 中 | 有限重试、错误日志和阻断状态 |
| 研究链接失效或内容变化 | 中 | 保存元数据，但未保存内容快照 |
| CI/Docker 尚未在本机实跑 | 中 | 本地测试通过，等待 GitHub/Docker 环境验证 |

## 8. 推荐后续顺序

1. 接入真实大模型并完成 Agent 执行审计；
2. 确定获得授权的正式资产和基准数据；
3. 修正交易日历、复权、费用和调仓生效模型；
4. 建立身份认证、角色权限和可信审批；
5. 运行至少三个月前瞻模拟盘；
6. 完成 Docker、CI、备份恢复和告警演练；
7. 通过合规评估后再考虑公开试点。

## 9. 下一里程碑建议

下一里程碑应定义为：

> 使用真实数据和真实模型，在不自动交易的前提下，连续运行一只组合的受控模拟盘，并完整保留每周研究、风控、审批、版本、业绩和月度复盘。

建议验收周期不少于三个月。只有在数据稳定性、流程执行率、风险规则有效性和样本外表现达到预设标准后，才进入面向外部用户的产品化阶段。
